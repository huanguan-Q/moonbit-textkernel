# Proof report

This page summarises what `moon prove` actually establishes in this repository
and what it does not. It is deliberately narrower than the word "verified" can
suggest.

## Current status

| Gate | Result |
|---|---|
| `moon prove` with stock solver limits (mathematical integers) | 207 goals proved, 3 timeout, 0/1 proof-enabled package |
| `node scripts/prove_gate.mjs` (CI, 32-bit machine integers, 10x limits) | every goal proved, 1/1 proof-enabled package (355 or 488 goals across five clean runs) |
| Backends tested | wasm, wasm-gc, js, native |
| Tests at last full run | 215/215 on each backend |

Measured 2026-11-27 on moonc v1.0.0-rc1 (`moon 0.1.20261126`), Why3 1.7.2,
Z3 4.15.4 and Alt-Ergo 2.4.3.

**The gate is the verdict.** The stock run and the gate prove different
theorems under different budgets: the stock run uses the mathematical-integer
prelude, in which "no overflow" cannot even be expressed, with a few seconds
per solver call. That its three slowest goals — all in the escape kernels —
report a timeout there is not by itself a regression. The outcome of a stock
run depends on solver timing; before the URL and filename rules were added,
the same kernels had a goal at the stock limits that z3 alone could not close
in 30 seconds, and Alt-Ergo happened to close it.

CI runs the gate on `ubuntu-22.04` with Why3 1.7.2, Z3 4.15.4 and
Alt-Ergo 2.6.x. `scripts/why3_dual_solver.mjs` rebuilds the verified
Alt-Ergo + Z3 strategy from the config generated by the CLI, and
`scripts/why3_conf.mjs` scales its limits (`PROVE_TIME_SCALE=10` in CI). This is
necessary because newer MoonBit CLIs emit a Z3-only strategy that times out on
runners.

## What is proved

All of it for the code-unit kernels in `src/proof/*.mbt`, which operate on
`FixedArray[Int32]` UTF-16 code units. The specification is
`src/proof/spec.mbtp` and `contains_spec.mbtp`.

- **HTML escaping** (`escape.mbt`): the output contains no `<` or `>`, the
  attribute variant also no `"` or `'`; every `&` starts one of the five
  entities; the length stays within `5n` / `6n`; and each written segment is
  exactly the escape of its input unit. A surrogate unit is copied when it is
  half of a well-formed pair and replaced by `_` only when it is unpaired
  (`paired_at`, `lone_surrogate_at`).
- **Filename sanitising** (`sanitize.mbt`): every result unit is `_` when the
  input unit was one of `/ \ : * ? " < > |`, a C0 control, DEL or an unpaired
  surrogate half, and is the input unit otherwise; the length is
  `adjusted_len`, so the clamp never falls between the halves of a pair and is
  never zero; a name made of dots only yields the default name `file`.
- **Scheme, authority and host** (`url.mbt`): `http://` and `https://` are
  recognised in any letter case; `authority_end_codes` returns the first
  delimiter at or after a position, or the end; `host_start_codes` returns the
  index after the last `@`; a host equals an entry, or ends in a dot followed
  by the entry, ignoring ASCII letter case; the `http://` → `https://` rewrite
  carries the tail over verbatim; the referrer decision is exactly "an http(s)
  URL whose host passes the host rule".
- **Substring search** (`contains.mbt`): the result is true exactly when the
  needle occurs somewhere in the haystack.
- **Chunk arithmetic** (`batch.mbt`): a non-positive size clamps to 1; the chunk
  count and the chunk end have exactly their stated values, for
  `0 < bs <= MAX_CODE_UNITS` and `n <= MAX_CODE_UNITS`.

`src/proof/codes.mbt` supplies explicit `proof_require` bounds against
`MAX_CODE_UNITS`, so the 32-bit machine-integer model can prove overflow
safety instead of leaving it inexpressible. Lengths are required to be
non-negative explicitly as well: the prover does not know that on its own.

`src/proof/conform.mbt` pins each proved kernel to the shipped `String`
implementation over an enumerated corpus, including well-formed surrogate
pairs, the clamp when a pair straddles it, and the historical
`UInt16::to_string` digit bug.

## What is not proved

- The prover has no model for MoonBit `String`. Conformance is corpus
  equivalence, not a theorem about every `String`.
- Only `src/proof` sets `proof_enabled`. `src/lib`, `src/main`, `src/cli` and
  `src/demo` are outside the proof denominator.
- `src/lib` closes that gap with runtime invariant checks before returning.
- `batch.mbt` proves arithmetic only: no scheduling, concurrency or timing.
- Two rules of the shipped URL routine are not modelled: stripping the port
  from a host, and the parsing of the query. Two rules of the shipped filename
  routine are not modelled: trailing dots and spaces, and Windows device
  names. All four are covered by tests and by the runtime invariant
  `filename_is_sanitized`.
- Where a platform rule applies to a name, the sanitizer bridge abstains
  (`sanitize_platform_rules_are_identity`), and that abstention is asserted,
  not passed for free.
- A lone surrogate half cannot be written in a MoonBit string literal, so no
  corpus can carry one through the shipped `String` functions. The kernels are
  driven on raw code units, and the WASM exports are exercised from a JS host
  in `examples/wasm-node/demo.mjs`.
- The host allow-list and default query parameters are data, injected through
  `AssetConfig`; changing them does not require re-proving the kernels.
- The functional property of the escapers is an assertion per iteration, not a
  postcondition over the whole output; a postcondition would need a prefix sum
  that SMT does not close (see the note in `escape.mbt`).
- A proof is about its specification. The first specification of the escapers
  replaced every surrogate unit and was proved faithfully; the specification
  was wrong, and an emoji came out as `__`.

## Reproduce

```bash
moon fmt --check
moon check --target all --deny-warn
moon test --target all
moon prove                # informational: 207 goals, 3 timeouts at the stock limits
node scripts/prove_gate.mjs   # the verdict
```

The gate fails loudly if a proof-enabled package is skipped, if the package
count disagrees with the sources, if a package proves zero goals, or if any
failure line contains an invalid/timeout/unknown goal. The *number* of goals is
not a stable contract because `split_vc` can close goals earlier; the stable
claim is `N of N packages proved` with no unproved goals. In five clean runs of
the gate on 2026-11-25 the count was 355 three times and 488 twice.

## Interpreting the claim

Say "the code-unit kernels are proved and the shipped String layer is pinned by
a conformance corpus plus runtime invariant checks." Do not say "the whole
library is formally verified."
